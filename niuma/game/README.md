# 代码题 · 《植物大战僵尸 · 打工人版》

> 给 8 家 AI 同一份任务书，各做一个**能离线双击运行**的 3D 体素网页塔防；再由 8 位 AI 评委盲评 + 客观脚本核验。
>
> 题面见 [`TASK.md`](TASK.md)；各家产出见 `../../submissions/niuma/game/`；结果见 `../../results/niuma/game/results.md`。

---

## 一、出题

| 项 | 要求 |
|---|---|
| 形态 | 一个文件夹，入口 `index.html`，**双击即玩**（`file://`，无服务器、无构建） |
| 渲染 | 真 3D（WebGL）+ **固定半俯视、正对战场、无横向偏转**，5×9 战场与左侧 5 个工位一屏可见 |
| 资源 | **零外部资源**：不许 CDN、字体、图片、音频，连 base64 内嵌也不行；所有声音用 WebAudio 运行时合成 |
| 玩法 | 机制对标 PvZ：咖啡因经济 / 拖拽种植 / 铲子 / 12 波 / 工位槽位 / 年假 / 辞职信赌局 / 5 种敌人 |
| 自创 | 每件必须自创 **2 个**打工人单位，机制不能是"换皮直线射手" |
| 数值 | **完全交给模型自己平衡**，只锁单位机制与相对关系——"能不能调平衡"本身是考察项 |

任务包另含两件输入：`lib/three.min.js`（Three.js r147，可用可不用）与 `refs/crossy-road.jpg`（体素美术基准）。

## 三、怎么评

**盲评 60**（8 位评委，取均值）—— 评委只拿到源码与 3 张证据图，**不试玩**：

| 维度 | 分 | 依据 |
|---|---|---|
| 视觉与美术 | 20 | 只看 3 张证据图 |
| 可玩性与平衡 | 25 | **读代码**：难度曲线 / 交互实现正确性 / 系统完善度 |
| 创意与主题 | 15 | 自创单位的机制区分度 + 主题还原度 |

**客观 40** —— 由核验脚本与人工试跑给出：功能完成度 30（覆盖 15 + 缺陷修正 15）＋ 声音 10。
4 项硬门槛（`file://` 无报错 / 可玩 / 真 3D 正对一屏 / ≥30fps）任一不过即不合格。**8 件全部通过**。

> 证据图三张：`01-hud-cards.png`（主界面手牌卡）、`02-units.png`（单位摆拍集合）、`03-gameplay.png`（实战一帧）。
> 其中 `02`、`03` 是**组织者按同一机位规格摆拍/采集**的，8 件之间横向可比；它们**只用于看画面**，不能用来推玩法或数值——玩法一律以代码为准。

## 四、怎么复现

1. 取 `submissions/niuma/game/<模型>/` 整个目录（或用 Release 里的 `game-8.zip` 解压）
2. 双击 `index.html`，最新版 Chrome，1080p 窗口
3. 每件的 `review/` 里是评审用的三张证据图与两份对照材料：`cheatsheet.md`（组织者从源码摘抄的数值与机制速查，逐条带 `文件:行` 出处）、`design-doc.md`（作者写在 `index.html` 顶部注释里的设计说明，原样抽出）

`lib/three.min.js` 已随每件作品各带一份（体积约 0.6 MB，8 份重复）。这是原始交付的样子——为的是解压后**不跨目录**也能直接双击运行，故未做合并。
