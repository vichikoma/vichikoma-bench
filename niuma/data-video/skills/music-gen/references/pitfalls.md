# 坑清单（都已实测踩过）

## 环境 / 调用

1. **刚装好的软件，旧进程可能看不到**。装到系统 PATH 的 FluidSynth，已经开着的终端 / 编辑器 / Agent 进程不会自动刷新 PATH。
   → 重启那个进程；或者干脆不依赖 PATH：用环境变量 `FLUIDSYNTH` 指向可执行文件，或把便携版放进 `bin/`。

2. **路径里有空格或中文时手动敲命令要加引号**。`C:\Users\张 三\...` 会被 cmd 拆成两段。
   用 Python 的 `subprocess` 并以列表传参不受影响（本库就是这么调的）。

3. **Windows cmd 不支持多行命令**（会被静默截断）。要么写成 `.bat`/`.py` 文件，要么用 `&&` 串起来。

4. **`mido` 没有 `__version__` 属性** —— 别用它验证版本，用 `pip show mido`。

5. **音源文件很大，国内下载极慢**（30MB 在 raw.githubusercontent 约需 330s，jsdelivr 对 >20MB 直接 403，
   多数 GitHub 镜像不通）。所以音源随 Release 的 `niuma-music-gen-win-x64.zip` 一起发，正常情况**不需要再下载**。

## 作曲

6. **叠音函数必须处理负起始时间**。引子提前 0.3 拍起音会产生负 tick → mido/索引报错。
   本库 `Piece` 会把事件排序后算 delta，负 tick 需自己避免（或改用 `max(0.0, t)`）。

7. **`note_off` 与同音 `note_on` 在同一 tick 时，顺序错了会漏音**。
   本库用 `(tick, priority, seq)` 排序，`note_off`(1) 排在 `note_on`(2) 前，已规避。

8. **只有很少声部时，开头会低到 −40dB 听着像坏了**。加低音 drone 托底（主音/五度长音）。

9. **所有声部都挤在同一音区 → 一定糊**（250–800 Hz 堆积）。把各声部的音区拉开。

10. **力度全设成一样 → 层次感全无**，每秒 RMS 轮廓会是一条直线。

## 渲染

11. **FluidSynth 默认 `-g 0.2`**，非常小声；建议 `--gain 0.6`，最后靠母带归一化。

12. **渲染结果比 MIDI 长**：末尾会带上释放 + 混响的余响（约 +5~7s）。
    这正是 tail-fold 的原料，**不要当成 bug 删掉**。

13. **混响默认就开着**（`-R` 默认 on）。要干声必须显式 `--reverb off`。

14. **GM 打击乐固定走通道 9**，pitch 是鼓件号不是音高。`p.track(..., drums=True)` 已处理。

## 母带 / 输出

15. **GM 音源光靠 CC10 pan 做不出立体声宽度**（实测相关度只到 0.94）。
    必须「极端 pan + 左右分轨 + M/S 展宽」三件套。详见 `qa-standards.md`。

16. **归一化前要检查 peak 是否为 0** —— 全静音时除法会炸。

17. **游戏用循环不要加淡出**（`--fade 0`）。淡出只适合当独立曲目试听。

18. **`ffmpeg` 缺失时导出会静默跳过 ogg/mp3**（本库会打 warn）。
    Windows 上若没有：`winget install Gyan.FFmpeg`。

19. **`.ogg` 是 Web/微信小游戏的首选格式**（体积最小、循环友好）；`.wav` 用于需要无损或引擎要求。
